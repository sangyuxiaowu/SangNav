# 云端账户与数据存储

账户、密码和会话使用 AES-256-GCM 加密后保存在 IndexedDB，密钥为不可导出的 Web Crypto CryptoKey，不保存明文密码。刷新或重新打开页面自动恢复有效会话；到期前及接口返回 `401` 时，使用加密凭据自动重新登录获取新令牌。服务器不提供 refresh token，此处调用现有资源登录接口，不延长原令牌有效期。

自动重新登录仍受服务端登录限流约束；密码错误或账户禁用时停止自动重试、清除保存的账户凭据并保留数据草稿，需要手动重新登录。网络异常不会删除已保存的账户。退出账户会删除加密凭据和密钥。加密存储要求安全上下文（HTTPS 或本机开发地址）及 IndexedDB；不可用时会提示刷新后需手动登录。加密不抵御同源恶意脚本或已被控制的浏览器，仅避免凭据明文落盘；只在可信设备上使用。

需要服务端允许当前网页来源访问 API。空间地址要求 HTTPS，本机 `localhost`、`127.0.0.1` 和 `::1` 开发地址可使用 HTTP。登录后检查 `/capabilities` 的 `apiVersion=v1`、Bearer/workspace 认证，以及 `resources.json`、`resources.conditions`、`commits.atomic`；缺少必需能力则拒绝连接。读取实际 `limits` 约束分页、正文、附件及提交大小，不调用未实现的分享、AI 或离线同步接口。登录 `429` 按 `Retry-After` 阻止提前重试，自动登录的临时失败稍后重试，不立即清除账户。

云端数据归属规范化的空间 URL，同一 URL 的资源账号看到同一套数据，不同 URL 相互隔离。云端键不包含账号 ID，不再使用单快照。资源格式为 `sangnav.resource`、版本 `1`，JSON 正文使用 `{ "value": ... }` 包络，以支持空图案锁等空值。

| 逻辑键 | 内容 |
| --- | --- |
| `app.json` | 数据格式标识 |
| `settings.json`、`wallpaper.json` | 一般偏好、壁纸及附件引用 |
| `links/<id>.json`、`categories/<id>.json` | 单个书签、单个分类 |
| `links/order.json`、`categories/order.json` | 顺序及完整性清单 |
| `secret/links/...`、`secret/categories/...` | 私密书签、分类和顺序 |
| `secret/pattern.json`、`secret/autolock.json` | 图案锁及自动锁定 |
| `search/engines.json`、`search/active.json` | 搜索配置 |

搜索历史提示仅在本机按账号隔离保存，不参与配置草稿。访问与搜索统计分别进入 `analytics.visits`、`analytics.searches` 通用事件流，不再生成普通资源或日分片。本次按新应用结构接入新空间，不提供旧云统计格式迁移。

启动优先恢复同空间、同身份的本机缓存，立即显示导航、搜索和设置，不使用全屏等待遮罩。云端基线独立保存于 IndexedDB，包含完整资源正文、key/id/version、未知格式占用键、storeRevision 和最近成功检查时间；编辑草稿单独保存其原始版本。缓存按完整空间 URL、账号和固定读取范围隔离，草稿额外按标签页隔离。读取期间保留编辑，失败不回退默认导航，也不推进成功检查时间。

完整且验证通过的基线在 5 分钟内不发资源同步请求，认证和能力检查不计入此限制；其他设备的变化可能延迟约 5 分钟被发现。过期先请求 `/read-state`，修订字符串相同仅更新检查时间；手动核实/读取云端绕过新鲜度窗口。缓存损坏、业务校验失败或格式范围变化不能跳过读取。

首次加载及全量恢复在同一读取栅栏下收齐摘要，仅对新增、变化或缺少正文的资源读取正文；必须同时匹配 key、id、version 才复用正文。同 key 更换 UUID 必须重读。支持 `resources.batch-read` 时使用 `POST /resources/batch-read`，按运行时条数及 UTF-8 请求字节限额分批，并处理响应容量造成的连续前缀：只重新提交当前数组的 `items.slice(nextOffset)`，不累计旧偏移。413 有界拆分，单项改用 GET；逐项缺失、顺序或版本不匹配均终止候选读取。旧服务端仍按最多六项并发逐条 GET。

完整基线修订变化且支持 `resources.changes` 时，优先读取空间级增量，不扫描全部摘要。所有索引页必须保持相同 sinceRevision/targetRevision，仅携带 nextCursor 续页；校验修订区间、重复 ID 和循环游标。收齐索引后，按 ID 移除全部变化项的旧云端条目，再加入管理范围内的非删除正文，避免同 key 删除旧 ID 与新建 ID 互相干扰。改名、格式改变及移出管理范围均按目标状态处理。正文按指定 id/version 批量读取不可变历史版本，不携带旧读取栅栏；仅以增量 targetRevision 推进基线，不采用历史正文响应中的当前 Store-Revision。缺少批量能力但支持历史修订时按版本 GET；两者都缺失则回退全量。

增量 410 且 fullSyncRequired=true 时保留旧视图和草稿，重新取得修订并有界全量恢复；其他失败不推进基线。旧缓存对未知格式只保存占用 key、未保存其 ID，因此存在此类占用时保守采用全量读取，以正确处理未知资源改名或删除。新遇到未知格式仍保留覆盖保护。没有增量能力时继续采用摘要比较路径。

列表、正文、顺序及分类引用全部校验后才原子保存候选基线。本地草稿不覆盖唯一云端基线，局部提交成功只推进确认成功的资源版本，并使整份基线的空间修订失效，下次重新检查，不能将旧数据绑定到新修订号。Web Locks 按空间和账号协调检查、提交和事件上传，取得锁后重读共享状态；BroadcastChannel 通知其他标签页重新读取并合并各自草稿。无 Web Locks 时降级为单页面串行，跨标签页仍依赖版本条件和事件去重保证写入安全；无 BroadcastChannel 时通过下次检查发现其他标签页变更。

## 事件与偏好统计

点击、搜索先同步将稳定 eventId、毫秒 eventTime 和完整 payload 保存到按空间/账号隔离的本机持久队列，之后后台批量 POST 根数组。正常操作不等待上传，不改配置 dirty 状态，也不触发配置的 beforeunload 离页保护。搜索历史同样不进入配置保存。真正未保存的书签、分类或设置编辑仍有离页保护。

不能直接使用 sendBeacon：事件 API 需要 Authorization Bearer 头，而 sendBeacon 不能自定义该头。页面隐藏/离开时使用带授权的 fetch keepalive 尽力发送小于 48,000 字节的批次，正常后台上传遵循运行时条数/UTF-8 字节限额；不依赖关页上传成功。网络错误和 5xx 原 ID 有界退避重传，429 持久保存 Retry-After，只有 acceptedCount + duplicateCount 完整确认后才移除队列项。400/409/413 不盲目自动循环，保留整批并在统计页显示状态。断开或更换账号不会把原队列发到新空间。

配置首屏不查询历史统计。进入统计页后，面板只提供近 30 天、近 7 天和今日，所有请求显式限制范围，今日使用本地自然日边界。云端通过 `/streams/{streamType}/aggregate` 顺序执行全局卡片、域名 TOP 12、小时分布、搜索词 TOP 10 和引擎分布查询。站点仅按 domain 分组，小时使用 eventTime 的 hourOfDay 和浏览器 IANA 时区；缺少小时补零。去重总数和占比使用独立全局指标，不拿 TOP N 结果之和冒充全量。截断的引擎分布补“其他”。聚合失败不自动反复重放，也不改变资源修订。

原始事件查询只在明确调用时执行固定时间窗口分页，只以 nextCursor=null 判断结束，翻页仅传游标；每轮按 eventId 去重并合入尚未确认的本机队列，不把游标保存为可靠同步水位。服务端事件不自动保留 30 天或自动删除；30 天仅是客户端统计范围。事件接口没有单条删除，因此云端模式禁用“清空统计”，本机模式仍可清空。配置备份不包含独立云端事件流；首次导入本机配置也不自动上传本机统计。

保存只提交变化的资源，通过 `/commits` 传递完整资源及各自的 `expectedVersion`；`null` 表示创建，正整数表示条件更新或删除。这是资源级增量保存，不是 JSON 字段级 PATCH。普通提交按能力响应的 `limits.commitOperations` 校验，不额外硬编码 50，但当前服务端仍限制单次最多 50 项。公共导航、私密导航及偏好组的关联修改各自保持原子性，只有明确独立的组允许分别提交。

服务端支持 `commits.staged` 时，首次同步、完整备份恢复和超出普通提交上限的变更使用一个暂存会话：先把所有批次上传至暂存区，最终一次发布才使在线资源整体生效。完整默认数据可以分多批传输，但不是多次独立发布。小规模修改继续使用普通原子提交。普通单次上限仍为 50，暂存单会话可达 10,000 项，数量和字节限制均读取实际能力响应，不在客户端固定为 50 或 100。缺少暂存能力时仅支持独立业务组分批，关联组和完整恢复不得拆散。

首次请求前把完整草稿、变更计划、commitId、原始 UTF-8 批次正文和读取基线持久保存在 IndexedDB。持久化失败则不发送暂存请求。刷新或重新登录同空间、同账号后，读取原计划并查询同一会话，仅补传缺失批次，核对已上传批次的 SHA-256。确认 published 且收齐结果分页、校验 ID/顺序/版本后才推进同步基线；上传完成不代表云端已保存。整个关联组超出暂存总配额时仍会拒绝发布，完整保留数据，不要求删除数据规避。

会话默认 24 小时过期、终态回执默认保留 7 天，均以能力响应为准。404/410 或账号不可访问不证明从未发布，保留原提交标识，不自动换 commitId 重做。版本或空间基线冲突时不能更改旧批次；可先核实回执，或明确选择读取云端以取消未发布会话、重建基线后再恢复备份。已发布提交不能取消。暂存计划绑定原资源账号，不会由同空间其他账号续传。

断网、认证失效或版本冲突会保留草稿，不显示已保存。提交超时、网络中断、`5xx` 或无效回执显示“结果待确认”。暂存的「核实并重试」先查同一 commitId 的状态与摘要，再补批或查询发布回执，不换标识或重序列化批次。普通提交仍无幂等保证，必须先读取相关资源核实，不能盲目重放。不能为了消除冲突读取最新版本覆盖旧草稿。冲突时先完整备份，再选择读取云端或进行业务合并。

服务端支持 `resources.read-fence` 时，先 `GET /read-state` 取得十进制字符串 storeRevision，全部列表页和当前正文带 `If-Store-Revision`，并检查每个成功响应的 `Store-Revision`。修订号不转换成 JavaScript Number。409 且 reason=read_revision_changed 时丢弃整轮候选缓冲，最多重新读取三轮；仍失败就保留旧视图与草稿。正文、顺序及分类引用校验完成后才一次替换视图。暂存发布可携带该读取基线，空间变化会保守冲突，不能把新修订号直接套给旧草稿。

缺少读取栅栏能力时保留旧版候选加载及业务校验，但不宣称跨请求快照保证。即使有栅栏，读完以后远端也可能再次变化，后续写入仍必须使用草稿对应的资源版本。任何路径都不根据分页缺失项生成删除。

已删除资源 UUID 不可复用。恢复历史内容必须创建新 UUID 并更新相关业务引用；当前仍存在的资源回退内容，则基于当前草稿对应的 JSON 版本正常条件更新。服务端源码生成强数字 ETag；接入部署曾出现弱 ETag，原因尚未确认，不推定是源码、压缩或代理导致。

退出后恢复原本机数据，不把云端内容写入本机模式。同一标签页下次以相同身份登录相同空间时恢复草稿，不会把上一身份的未保存修改自动上传；这不改变云端数据的空间级共享语义。浏览器存储不足时提示立即完整备份。配置备份包含私密导航和图案锁，不包含独立事件流；普通导航备份仍只包含普通导航数据。注销返回 `401` 视为会话已失效；其他注销失败仍清除本机令牌并显示错误。

本地壁纸以原始图片字节上传，检查附件能力、大小、SHA-256 和返回的媒体类型后，在 `wallpaper.json` 中声明附件引用。附件按空间/账号及 ID/哈希持久缓存，校验后复用；缓存缺失或损坏时单独补取，不清除配置草稿。上传已收到 ID 但校验失败时，错误对象和本机待核查记录保留该 ID。已验证上传在资源提交失败后仍保留标识，核实重试时复用，不重复上传。不把整个数据集作为附件保存。单个书签等仍受正文大小上限约束，超限保留草稿并提示。附件历史由服务端保留，不自动删除历史或未引用附件。天气和远程图标仍为本机缓存，自定义图标配置随对应书签资源保存。

服务端与本机草稿均无端到端加密，私密导航和图案锁也会上传。空间内资源账号具有整个空间的读写权限；需要权限隔离时使用不同空间。勿在不可信设备上登录或保留完整备份。
